# Agent Collaboration · 协同作战室

一个**群聊式多智能体协同系统**：用户在一个作战室里 @ 成员派活，主智能体与子成员在同一个群聊中协作、汇报，所有过程、任务与文件都可观察。

本项目是一套自研的轻量 TypeScript 运行时（Node + Express + React），核心调度、上下文预算、记忆检索，以及部分健壮性机制深度参考并移植自 OpenClaw（MIT，相关文件保留版权声明）。内置的 Word 文档技能改写自 wintersdragon-c/office-docx-skills（MIT，Copyright (c) 2026 wintersdragon-c，脚本文件头保留出处与改动说明）；技能说明里的联网、数据、工程类内容另有各自的开源来源，均记录在技能的「来源」字段上。

当前版本：**v1.7.0**

## 功能特性

- **群聊式协同**：主智能体负责拆解与分派，成员以 @ 提及接收任务，完成后在群里汇报并唤醒上级汇总；运行状态通过 SSE 实时推送。
- **双模式协同**：标题栏可在「委派」与「自由交流」间一键切换。委派模式由主智能体拆解分派、成员只对分内任务汇报；自由交流模式允许成员直接 @ 彼此讨论，讨论安静后由主智能体统一收集并总结。模式随房间持久化。
- **取人方式（`lead` / `everyone` / `auto`）**：只回答「一条谁都没 @ 的消息交给谁」这一个问题，显式 @ 与成员之间的汇报链路一律不动。`lead` 是原来的行为（交主智能体拆解分派）；`everyone` 同时唤醒在场成员（含主智能体兜底，一条消息最多 6 人开工），与自己无关的成员回一个 `pass` 就保持沉默（`pass` / `(pass)` / `【pass】` 都认，界面不会看到这句被当成发言）；`auto` 先花一次不带工具、`temperature=0`、`max_tokens≤200` 的小调用，只喂花名册加最近 5 条各截 600 字，要求严格输出 `{"members":[...]}`，名单非法或调用失败就回落 `lead` 并在群里说明一次。挑到人就不再补主智能体的综合汇报，被点名但还没开口的同伴会自动进下一轮，轮转顺序按消息序号偏移保证没人被永远排在最后。计划轮不参与分流。房间级设置随房间持久化，标题栏三档开关即时生效；分流那一次调用与成员运行记在同一本用量账里。
- **顾问扇出（MoA 的群聊版）**：设置里的「顾问扇出」默认关闭——不开就多一次调用都不花。开启后，动手的成员在执行前先请在册成员按花名册顺序出 1–3 份主意（自动排除它自己）：每位顾问拿到的是一份刻意削薄的「建议视角」——不含系统提示词、工具调用折成一行、单条材料按头 2000 + 尾 2000 字截断并写明省略了多少字、整份预算 2 万字并从最旧的开始丢，最多回看 20 条；提问角度固定为稳妥 / 发散 / 挑刺，靠温度区分，同一个密钥也能用。顾问被明确告知「你不是执行者，绝不声称已执行、不许调用工具」，没回话的那位在建议块里标 `[未产出：原因]`，全失败时整块不注入（`loud` 会在群里说明一声，`silent` 安静跳过），执行成员照常干活。建议块带标签交给动手的成员，并要求它点明顾问之间意见冲突时自己站哪一边、为什么——光有几份互相复述的建议没有意义。节奏可选「每个用户回合一次」（同一回合复用，靠缓存不再重复花钱）、「每次运行都问」、或「每 N 次运行问一次」（第一次一定问，间隔 2–8）；顾问模型可单独指定，留空跟随动手成员的模型。参谋意见走逐轮消息通道注入，系统提示词一个字节都不改；顾问花费照常进用量账本，在「模型设置 → 用量」看得见。
- **群聊区**：侧边栏「群聊区」可以按主题新建任意多个群聊（上限 50 间），从作战室成员池把成员拉进群，也可随时移出。进入某间群聊后，界面与作战室完全一致——聊天、@ 派活、任务看板、文件工作区、归档都能用；每间群有独立的聊天记录、任务卡与归档，成员档案、技能与文件工作区在全账号内共享。新建群聊默认包含主智能体；群名可改、群可删，删除当前群会自动回到作战室，成员池与其他群不受影响。侧边栏会标出当前所在群，并可一键返回作战室。
- **每用户独立房间**：管理员创建账号，每个账号拥有独立的作战室、成员、任务、设置与文件工作区，数据互不可见。管理员还可在「用户管理」里重置他人密码或删除账号——删除会一并清除该账号的登录会话、作战室记录与文件工作区、会话归档、个人技能和个人模板（共享技能与内置模板保留），且不能删除自己。
- **任务看板**：任务卡由智能体创建、更新与登记产出；右侧面板可在「任务 / 文件 / 归档」间切换。
- **文件工作区**：上传、下载、预览、删除与多级目录导航；用户与智能体共用同一 `files/` 目录，智能体通过 `file_list` / `file_read` / `file_write` 读写成果。`file_write` 支持 `append=true` 续写，长文档可以分节装配而不必整篇重写（`append` 与 `overwrite` 互斥）。
- **成稿与汇报分离**：智能体的系统提示词里有一条通用「交付文档」契约，适用于报告、方案、纪要、说明书、论文、合同、手册、简报等任何给别人看的成文材料，不绑定某一种文体。动笔前先定读者、用途、已知前提与篇幅；正文以连续段落为主，术语首次出现给定义，数据写明年份/口径/来源，不确定内容集中进「局限与存疑」；正文里不写内部分工、工具调用与文件指纹。群聊里的 @ 汇报仍然只给结论、证据路径与未解决项，成员汇报不会直接被拼成文档——主智能体负责统稿（统一口径术语与时间、补背景与结论、删过程性内容、顺章节过渡）。
- **完成标准与真实性准则**：所有智能体的系统提示词都无条件带一段行为准则（移植自 Hermes 的任务完成契约）——交付物是真的产出而不是对产出的描述，禁止用「看起来合理」的编造内容顶替真实结果（编数据、编文件内容、编接口返回、编运行输出），受阻时如实说明卡在哪一步并换路径；「完成」等于每条被点名的验收项都验证过；改动外部状态后必须回读确认，调用成功不等于任务成功；缺背景先自查、查不到就列出缺什么，不按猜测交付；冲突时优先级为「用户本轮指示 > 角色档案 > 长期记忆 > 默认规则」。配套的分工契约是：主智能体 @ 派活时必须重述背景（路径、错误原文、约束、完成标准、输出语言，成员看不到它这轮的推理），并把成员汇报当成**自述**而不是事实——要求带可核验的把手（文件相对路径、任务卡 ID、链接），自己 `file_read` / `task_list` 回读确认后才对用户说「已完成」。
- **会话归档**：`/clear` 把群聊记录、任务卡与 `files/` 成果整体存成一份快照（存于 `archives/<归档ID>/`），清空后新一轮任务不会再看到上一轮的任务卡与产出。右侧「归档」标签列出每份快照的内容清单，点击「恢复」即可放回；恢复采用交换语义——当前内容先自动另存为新归档，因此可反复来回切换而不丢数据。智能体长期记忆与成员档案不进归档，也不受影响。
- **技能库**：共享技能与个人技能，支持从 `SKILL.md` 导入；按 9 个分类（协同与规划、调研与写作、数据分析、开发与测试、产品与文档、设计与可视化、网页与检索、智能体与技能、其他）自动归类，可按分类筛选、按关键词搜索并按分类分组展示；可为每个成员单独勾选允许使用的技能。内置技能可以自带脚本，随系统一起预装并在版本升级时刷新（用户自建的同名技能不受影响）。
- **Word 文档能力**：预装 `docx-writer`（Markdown 一键生成排版规范的 .docx，含中文论文档：A4、宋体 + Times New Roman、小四 1.5 倍行距、首行缩进 2 字符；并按文体给出成文结构——长文带封面/摘要/目录/背景/结论/资料来源，短文不硬加封面目录）、`docx-reader`（抽取现有文档的标题、列表、表格、公式与修订）、`docx-track-changes`（以 Word 修订模式留下可见红线）、`docx-formula`（写入 Word 原生可编辑公式 OMML），并配 `docx_inspect.py` 自检页面、字体、表格与修订计数。只依赖 python-docx 与 lxml，不需要 pandoc 或 LibreOffice。
- **智能体文件**：每个成员拥有 `MEMORY.md` / `USER.md` / `SOUL.md` / `IDENTITY.md`，可在右侧面板直接编辑保存。
- **成员能力档案**：主智能体工作区根部的 `TEAM.md` 随成员创建、引用模板、技能授权调整与移除自动同步，一个成员一段（职责、可用技能、来源模板、创建日期），并注入主智能体的系统提示词，让它在分派前就知道谁能做什么。手改过的段落不会被自动覆盖。
- **模板库**：侧边栏「模板库」内置 17 个随系统预装的智能体模板，覆盖技能库的全部 9 个分类（如深度调研员、会议纪要员、数据分析师、代码审查员、PRD 撰写、文档排版等），每个模板带着角色设定（写入成员的 `Role`）、气质与 Emoji、工作方式条目、技能范围与建议成员名。点「引用为成员」即时生成一个成员，模板内容落到它自己的智能体文件里，之后可逐条修改；已删除的技能在引用时自动忽略。个人模板可新建、编辑、删除，也能从内置模板「另存为个人模板」再改，仅自己可见；个人模板支持导出与导入：卡片上的「导出」下载 `template-<标识>.json`（只含设定字段，不带账号与时间戳），「我的模板」里的「导入模板」可一次选多个 JSON 或直接粘贴，导入只落进自己的库、不覆盖已有模板，标识撞车自动加序号，字段仍走同一套长度/分类校验；成员与智能体文件都会标注来源模板。用顺手的成员可以直接「存为模板」：点进该成员，在智能体文件面板顶部按当前设定生成草稿（职责取成员描述、工作方式只带档案里你亲手加的那几条、技能沿用它的白名单），在模板库的新建表单里确认后保存进「我的模板」，之后可反复引用为成员；主智能体同样可以，未改过的预置信条不会被当成他的设定。
- **命令执行**：智能体可用 `run_command` 在文件工作区内运行 Python / Node / Shell 等命令，用 `run_skill_script` 执行技能附带的脚本（自动展开技能文件、参数不经 shell；传 `cwd` 可让脚本直接在 `files/` 里读写，产出就能在右侧「文件」看到）；默认 30 秒超时、输出截断 32 KB。`.py` 脚本会自动挑选真正可用的 Python 解释器（优先 `PYTHON`，Windows 上依次尝试 `py -3`、`py`、`python`、`python3`），绕开 Microsoft Store 的 python 占位程序。
- **联网工具**：内置 `web_search` / `web_fetch`（含 SSRF 防护、正文转 Markdown、长度截断与续读），并预装对应内置技能。
- **斜杠命令**：`/help`、`/new`（归档聊天与任务卡、开一个与上一个任务无关的新会话，文件保留）、`/clear`（归档并清空作战室）、`/stop`、`/status`、`/context` 在浏览器本地执行，不进入聊天记录；`/plan` 是唯一发给智能体的一条，它把命令后面的议题作为这一轮的内容发出，只是这一轮的工具集被收窄（见下条）。输入 `/` 会给出命令提示，支持 ↑↓ / Tab / Enter / Esc。
- **运行姿态（`/plan` 计划轮）**：消息可以带一个 `runScope` 姿态标记，运行期按姿态表把本轮注册的工具集**白名单式**收窄——计划轮只留读取与检索类工具（`file_list` / `file_read` / `web_search` / `web_fetch` / `memory_search` / `memory_get` / `room_history` / `task_list` / `use_skill` / `read_skill_file`）加 `task_create`，`file_write` 被限制在 `plans/` 前缀内（`plans/../` 之类的越界写法先归一化再拒绝），`run_command`、`run_skill_script`、`cron`、`task_update`、`task_attach_artifact`、`memory_append`、`spawn_member` 一律不挂载；调用未挂载的工具会拿到「本轮姿态不允许」而不是「工具不存在」的回执，成员在这轮发出的 @ 也不会唤醒别人。姿态只影响本轮注册的工具与逐轮指令文字，系统提示词一个字节都不改（前缀缓存继续命中），普通轮拿到的是同一个未收窄的工具数组。这一轮产出的消息继承同一姿态，气泡上标「计划轮」，因此「只查不动手」是可验证的事实而不是对模型的口头要求。以后加新姿态（如只调研、只写作）只需在姿态表里加一行，命令分发与运行期逻辑都不用改。
- **提示词分层与供应商前缀缓存**：系统提示词按「稳定层 → 能力层 → 易变层」拼装——角色与协作规则、行为准则在最前，记忆/文件/命令/定时等按本轮实际注册的工具追加，花名册、任务标题、`TEAM.md` 能力档案与技能索引一律放到末尾的「当前群况」段。因此同一成员连续多轮的提示词前缀逐字节不变（有测试断言这一点），DeepSeek 等兼容 OpenAI 的供应商才能命中前缀缓存；供应商返回的 `prompt_tokens_details.cached_tokens` 已折算成用量里的 `cacheRead` 进入成本核算。一次运行内系统提示词只构建一次，运行中新到的群聊内容随用户消息传入，不会中途重建提示词。
- **运行可靠性**：单次运行步数用尽时自动基于已有进展收尾而非整轮报错；工具调用去重、失败重试、上下文预算与自动压缩、工作记忆检索。
- **自我复盘与技能自学（学习层）**：侧边栏「学习」面板汇总成员每轮交付后的复盘产出。交付后服务端另起一次不带工具的模型调用，同时判断「这轮有没有值得长期记住的事实、有没有值得沉淀的做法」。记忆提案在面板点「写入记忆」才写入该成员的长期记忆（主智能体写账号 `MEMORY.md`，子成员写 `agents/<成员ID>/MEMORY.md`），也可以「忽略」；候选条目要过长度、触发词与重要性校验，含密钥的内容一律拦截，与已有记忆或待确认提案重复的自动丢弃，单次最多 3 条。复盘提示词还带两条 Hermes 式的接地规则：记忆的依据只能来自本轮的用户消息或真实工具结果，指不出出处的「事实」不写、也不从零散线索推断用户本人的特质；**没跑通的做法不是技能**——试了几条路都不成、最后让用户自己去查的那段尝试，绝不能写成「可靠流程」或「推荐做法」，模型宁可返回空数组。技能提案展示名称、适用场景、分类、触发词和完整 `SKILL.md` 预览，只有点「创建技能」才会落成账号级个人技能，并在来源成员设了技能白名单时自动把它加进名单；单次最多提议 1 个，名称不合规、与技能库或待确认提案重名的一律丢弃。**技能永远不会自动创建**——即使学习模式选「自动写入记忆」，自动通道也只写记忆。面板的「复盘流水」用 产出提案 / 已写入 / 无所学 / 已跳过 / 失败 解释每一轮为什么没学到东西，新记录经 SSE 即时刷新。设置里的「学习」可切换关闭 / 待确认 / 自动写入、每几轮复盘一次（1–20）、每天最多几次（1–200），并指定用哪个模型复盘（留空则跟随成员自己用的模型）；定时任务等无人值守运行不复盘。已写入的记忆不会被自动删除，只有「忽略」这一种否决；已创建的技能同样不会被自动撤销，要删请在技能库里操作。

## 快速开始

要求 Node.js 20+（推荐 22/24）、npm 9+。

```bash
npm run check:env   # 安装环境自检（无需 node_modules 即可运行）
npm install
npm run web:build   # 构建 Web 静态资源到 web/dist
npm start           # 启动服务：http://127.0.0.1:8788
```

首次打开页面会引导创建管理员账号；登录后即进入自己的作战室。服务默认只监听 `127.0.0.1`，可用 `PORT` 环境变量修改端口。

### 开发模式

```bash
npm run dev        # 后端，tsx watch，8788
npm run web:dev    # 前端，Vite，5274，/api 代理到 8788
```

> 后端代码改动需要重启服务；仅前端改动执行 `npm run web:build` 后刷新页面即可。

### 环境检查

在另一台机器上部署时，先运行：

```bash
npm run check:env
```

脚本只使用 Node 内置模块，`npm install` 之前也能运行。它会检查 Node/npm 版本、源码是否完整、项目目录与 `data/` 是否可写、磁盘空间、依赖是否装齐、`web/dist` 是否已构建、npm 源连通性、默认端口占用，以及两项可选能力：Python 3 解释器（Windows 上会自动尝试 `py -3`、`py`、`python`、`python3`，识别 Microsoft Store 占位程序）和 Word 技能所需的 `python-docx` + `lxml`。退出码 `0` 表示可以安装/运行，`1` 表示存在阻断问题；Python 相关检查只会给出 `warn`，不影响退出码——没有 Python 时其余技能与命令执行照常工作，只是内置的 4 个 Word 技能无法运行脚本。

- 离线或使用本地缓存安装：`npm run check:env -- --offline`（跳过 npm 源检查）
- 供脚本/CI 读取：`npm run check:env -- --json`
- 补齐 Word 技能依赖：`py -3 -m pip install python-docx lxml`（Unix 用 `python3 -m pip install python-docx lxml`）

## 配置模型

进入「设置 → 模型设置」添加 OpenAI 兼容 Provider，填写 `baseUrl`、`model` 与 API Key。默认带有：

- `demo`：`mock` Provider，无需密钥，用于本地演示
- `deepseek`：`https://api.deepseek.com/v1` + `deepseek-chat`，填入密钥即可使用

API Key 只保存在本机 `data/workspaces/<userId>/settings.json`，不会写入仓库。

## 数据与安全

- `data/` 为运行时数据（账号、会话、技能库、模板库、各用户工作区），已在 `.gitignore` 中忽略，请勿提交。
- 密码使用 scrypt 加盐哈希；会话令牌只存哈希；登录失败限流；退出与改密会注销其他会话。
- 文件工作区与智能体文件接口均做路径归一化与越界校验，符号链接不跟随。
- 命令执行与联网抓取受同一工作区约束：命令的 cwd 只能位于 `files/`，子进程不继承 `*KEY*` / `*TOKEN*` / `*SECRET*` 等密钥类环境变量；命令仍以服务进程权限运行，请勿将其暴露到不受信任网络。
- 联网抓取限制为 http(s)、逐跳校验重定向并阻断内网/回环等地址。
- 学习层只经「受控追加」写记忆文件：候选正文里的密钥（`sk-`、`password:`、带凭据的 URL 等）会被拦截丢弃，写入通道仅限 `MEMORY.md` 与 `agents/<成员ID>/MEMORY.md`，不会改动 `SOUL.md` / `IDENTITY.md`，也不会自动删除任何已写入内容。
- 技能提案同样不会自动落地：只有用户在面板点「创建技能」才会写入个人技能库；`SKILL.md` 正文、描述与触发词都要过同一套密钥拦截，名称、长度与分类在提案时校验一次，创建时再由技能库做同名冲突与权限校验。
